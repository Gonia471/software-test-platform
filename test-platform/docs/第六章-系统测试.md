# 第6章 系统测试

本章对基于 B/S 架构的软件测试系统进行开发自测，从测试原则与环境、功能测试及简单性能验证三个方面说明测试过程与结果。功能测试针对各模块核心流程设计测试用例，以表格形式记录用例编号、测试项、操作步骤、预期结果及测试结果，用于验证系统是否满足设计要求。

---

## 6.1 测试原则与环境

### 6.1.1 测试原则

本阶段测试以开发自测为主，遵循以下原则：

- **重点覆盖核心流程**：优先验证登录、UI 用例的创建与执行、执行结果查看等主流程，保证系统主路径可用。
- **可重复执行**：测试步骤与预期结果明确，便于在不同环境下重复执行并对比结果。
- **问题可追溯**：对失败用例记录操作步骤与现象，便于定位与修复。

## 6.4 测试小结

开发自测围绕 API 代理、UI 用例 CRUD、执行实例、执行与详情、步骤编排、AI 步骤识别、报告展示及登录与 Token 等核心功能设计测试用例，并以表格形式记录。测试结果表明：上述核心流程通过自测后，系统可满足当前阶段的功能与易用性要求。未通过用例可根据表格中的操作步骤与预期结果进行回归测试与缺陷修复。后续可在此基础上补充角色权限、报告列表与统计、API 用例持久化与断言等更细粒度的用例设计。
