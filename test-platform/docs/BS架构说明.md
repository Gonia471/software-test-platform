# B/S 架构说明（论文可引用）

本文档明确本系统中**浏览器/客户端**与**服务端**的划分，便于在本地模拟部署并用于论文表述。

---

## 一、B/S 的含义与本系统对应关系

- **B（Browser / 浏览器端）= 客户端**：用户通过浏览器访问的界面，不直接连接数据库，只通过 HTTP/HTTPS 向服务端请求数据。
- **S（Server / 服务端）**：接收客户端请求、执行业务逻辑、访问数据库、返回结果。

在本项目中：

| 角色 | 对应本系统 | 技术 | 运行位置 |
|------|------------|------|----------|
| **客户端（B）** | 前端项目 `frontend/` | Vue 3 + Vite | 开发时：本机 `npm run dev`，浏览器访问；部署后：静态资源放在任意 Web 服务器或 CDN，用户在浏览器中打开。 |
| **服务端（S）** | 后端项目 `backend/` | Spring Boot | 开发时：本机 `mvn spring-boot:run`，监听 8080；部署后：放在服务器上常驻运行，对外提供 API。 |

**数据库（MySQL）** 属于服务端一侧：只被后端连接，浏览器不直连数据库，这是 B/S 的典型做法。

## 二、本地模拟时的架构图

```
┌─────────────────────────────────────────────────────────────────────────┐
│  用户电脑（本地模拟：同时跑“客户端”和“服务端”）                              │
│                                                                         │
│   ┌─────────────┐         HTTP (如 GET /api/xxx)         ┌─────────────┐ │
│   │  浏览器     │  ────────────────────────────────────► │  后端服务   │ │
│   │  (客户端 B) │  ◄────────────────────────────────────  │  (服务端 S)  │ │
│   │             │         JSON 响应                       │  :8080      │ │
│   │  展示 Vue   │                                         │  Spring     │ │
│   │  页面       │                                         │  Boot       │ │
│   └──────┬──────┘                                         └──────┬──────┘ │
│          │                                                       │       │
│          │  1. 访问 http://localhost:5173                        │       │
│          │     从本机拿到 Vue 打包后的 HTML/JS/CSS               │  JDBC  │
│          │  2. 页面里请求 /api/xxx → 由 Vite 或 Nginx 代理到 8080 │       │
│          │                                                       ▼       │
│          │                                                ┌─────────────┐ │
│          │                                                │  MySQL      │ │
│          │                                                │  (数据库)   │ │
│          │                                                │  仅服务端访问│ │
│          └────────────────────────────────────────────────┴─────────────┘ │
└─────────────────────────────────────────────────────────────────────────┘
```

- **客户端（B）**：浏览器 + 前端资源（Vue 打包后的静态文件）。开发时通过 `http://localhost:5173` 访问，前端再请求 `http://localhost:8080/api/...`（或通过 Vite 代理转发到 8080）。
- **服务端（S）**：Spring Boot 进程（:8080）+ MySQL。负责接口、登录、业务逻辑、读写数据库。

## 三、哪些在服务端、哪些在客户端（便于论文书写）

### 3.1 在服务端（Server / 后端）完成的工作

- 用户注册、登录与鉴权（JWT 签发与校验）。
- 接口测试：项目/接口的增删改查、执行 HTTP 请求、断言逻辑。
- UI 测试：用例管理、触发 Karate 执行、报告存储与查询。
- 所有数据库访问（MySQL）。
- 对外只提供 **REST API**（JSON），不直接输出 HTML 页面（页面由前端负责）。

### 3.2 在客户端（Browser / 前端）完成的工作

- 展示所有页面：登录、侧边栏、使用说明、接口测试/UI 测试的操作界面。
- 路由与前端状态管理（如 Pinia）。
- 调用服务端 API（Axios 发 HTTP 请求），拿到数据后渲染页面。
- **不**连接数据库，**不**保存密码等敏感信息（仅保存 token 用于携带请求）。

### 3.3 数据流小结（便于画图或写论文）

1. 用户在**浏览器**中打开系统（访问的是前端页面）。
2. 前端根据操作**向服务端发起 API 请求**（如 `POST /api/auth/login`、`GET /api/projects`）。
3. **服务端**处理请求、查库或写库、返回 JSON。
4. **前端**根据返回结果更新界面（如跳转、展示列表、提示错误）。

## 四、本地模拟与正式部署的对应关系

| 环境 | 客户端（B） | 服务端（S） |
|------|--------------|-------------|
| **本地开发** | 本机运行 `npm run dev`，浏览器访问 http://localhost:5173 | 本机运行 `mvn spring-boot:run`，监听 8080；MySQL 本机或同一局域网 |
| **正式部署** | 将 `npm run build` 生成的静态文件放到 Nginx/OSS 等，用户用浏览器访问该域名 | 将 Spring Boot 打成 jar 在服务器上运行，或放入 Tomcat；MySQL 在服务器或独立数据库节点 |

本地同时启动前端开发服务器和后端进程，即是在**一台机器上模拟** B 和 S 分离的架构；部署时只需把前端、后端拆到不同地址/端口或域名，架构不变。

---

## 五、论文中可用的简要表述

- 本系统采用 **B/S（Browser/Server）架构**：浏览器端采用 Vue 3 实现单页应用，负责界面展示与用户交互；服务端采用 Spring Boot 提供 REST API，负责业务逻辑与数据持久化；数据库仅由服务端访问，符合 B/S 架构的职责划分。
- 开发与演示阶段在本地同时运行前端开发服务器与后端服务，以模拟浏览器客户端与服务端的交互；部署时可将前端静态资源与后端服务分别部署，架构一致。
