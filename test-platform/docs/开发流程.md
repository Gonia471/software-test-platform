# 前后端开发流程（自研版）

本文档定义**自研软件测试系统**的前后端开发阶段与顺序，按步骤完成即可。统一技术栈：**前端 Vue3，后端 Spring Boot，数据库 MySQL**。

---

## 流程总览

| 阶段 | 名称 | 后端重点 | 前端重点 |
|------|------|----------|----------|
| 0 | 项目初始化 | Spring Boot 脚手架、数据库、基础配置 | Vue 项目脚手架、路由、基础布局 |
| 1 | 门户骨架与登录 | 用户表、登录/注册 API、JWT | 登录页、主布局+侧边栏、路由守卫 |
| 2 | 门户内容与入口 | （可选）文档接口 | 接口测试/UI 测试说明页 + 入口按钮 |
| 3 | 接口测试 - 后端 | 项目/接口 CRUD、发请求、简单断言 | — |
| 4 | 接口测试 - 前端 | — | 项目与接口管理、调试、执行结果 |
| 5 | UI 测试 - 后端 | 用例管理、Karate 执行、报告存储 | — |
| 6 | UI 测试 - 前端 | — | 用例列表、执行、报告查看 |
| 7 | 联调与收尾 | 联调、部署说明 | 联调、部署说明 |

## 阶段 0：项目初始化

**目标**：前后端项目可本地运行，数据库可连接。

### 0.1 后端

- [ ] 使用 [Spring Initializr](https://start.spring.io/) 或 IDE 创建 Spring Boot 项目，放入 `backend/`。
  - Java 17+，Spring Boot 3.x。
  - 依赖：Web、Spring Security、JPA（或 MyBatis）、MySQL Driver、Lombok（可选）。
- [ ] 配置 `application.yml`：端口（如 8080）、数据源（MySQL URL、用户名密码）、JPA 等。
- [ ] 创建数据库（如 `test_platform`），确保 `spring-boot:run` 能启动并连接数据库。
- [ ] 如需跨域：配置 CORS 允许前端开发地址（如 `http://localhost:5173`）。

### 0.2 前端

- [ ] 在 `frontend/` 下用 `npm create vue@latest` 或 Vite 创建 Vue 3 项目（Vue Router、Pinia 可选但推荐）。
- [ ] 配置路由（Vue Router）：先占位 `/login`、`/`（主布局）、`/api-test`、`/ui-test` 等。
- [ ] 配置请求基址（如 Axios baseURL：`http://localhost:8080/api`）。
- [ ] 确认 `npm run dev` 能跑起来（页面可空白）。

### 0.3 可交付

- 后端：`cd backend && ./mvnw spring-boot:run` 无报错，数据库连接正常。
- 前端：`cd frontend && npm run dev` 可访问，路由切换不报错。

## 阶段 1：门户骨架与登录 ✅

**目标**：用户能登录，登录后进入带侧边栏的主界面。

### 1.1 后端

- [x] 设计用户表：如 `user`（id, username, password_encrypted, created_at 等）。
- [x] 实现注册接口：`POST /api/auth/register`（用户名、密码，密码需加密存储）。
- [x] 实现登录接口：`POST /api/auth/login`，校验成功后返回 **JWT**（或 Session）。
- [x] 实现当前用户接口：`GET /api/auth/me`（需鉴权），用于前端获取登录态。
- [x] 配置 Spring Security：放行 `/api/auth/login`、`/api/auth/register`，其余 API 需携带 JWT 校验。

### 1.2 前端

- [x] 登录页：表单（用户名、密码），提交调用 `POST /api/auth/login`，将返回的 token 存入本地（localStorage 或 Pinia + 持久化）。
- [x] 主布局：左侧侧边栏（含「接口测试」「UI 测试」两个 Tab 入口）+ 右侧主内容区；顶部可显示用户名、退出。
- [x] 路由守卫：访问 `/` 或子路由时，若未登录则重定向到 `/login`。
- [x] 退出：清除 token 并跳转回登录页。

### 1.3 可交付

- 能注册、登录，登录后进入主布局并看到侧边栏；退出后回到登录页。

## 阶段 3：接口测试 - 后端

**目标**：提供项目、接口的 CRUD，以及「发送请求 + 简单断言」能力。

### 3.1 数据模型（建议）

- [ ] **项目**：`project`（id, name, description, user_id, created_at）。
- [ ] **接口**：`api_interface`（id, project_id, name, method, url, headers_json, body_json, created_at）。
- [ ] **断言（可选）**：`assertion`（id, interface_id, type, expression, expected_value）或简化为接口表内 JSON 字段。

### 3.2 接口设计（建议）

- [ ] 项目：`GET/POST/PUT/DELETE /api/projects`（列表、创建、更新、删除）。
- [ ] 接口：`GET/POST/PUT/DELETE /api/projects/{projectId}/interfaces`。
- [ ] 执行单接口：`POST /api/projects/{projectId}/interfaces/{id}/run`，后端用 RestTemplate 或 HttpClient 发请求，执行断言，返回响应 + 断言结果。

### 3.3 后端实现

- [ ] 实现上述 CRUD 与 `run` 接口；执行时解析 headers/body，发 HTTP 请求，若配置了断言则做校验（如状态码、JSON 某字段），将结果返回前端。

### 3.4 可交付

- 用 Postman 或 curl 能完成：创建项目 → 创建接口 → 调用 run 得到响应与断言结果。

## 阶段 4：接口测试 - 前端

**目标**：在「进入接口测试平台」后的页面中，完成项目与接口管理、调试、执行与结果展示。

### 4.1 页面与路由

- [ ] 路由：`/api-test/app`（或 `/api-test` 下默认）为接口测试主页（项目列表）。
- [ ] 项目列表页：展示项目列表，可新建、编辑、删除、进入某项目。
- [ ] 进入项目后：左侧接口列表，右侧接口详情/编辑（Method、URL、Headers、Body）+「发送」按钮。
- [ ] 发送后：展示响应状态码、响应头、响应体；若配置了断言，展示断言通过/失败。

### 4.2 与后端对接

- [ ] 调用阶段 3 的 projects、interfaces、run 接口，将结果渲染到界面。

### 4.3 可交付

- 从门户「进入接口测试平台」→ 能创建项目、添加接口、编辑、发送请求并看到响应与断言结果。

## 阶段 5：UI 测试 - 后端

**目标**：用例管理 API + 调用 Karate 执行并保存报告。

### 5.1 数据模型（建议）

- [ ] **UI 用例**：`ui_case`（id, name, feature_content 或 file_path, created_at）。
- [ ] **执行记录**：`ui_run`（id, case_id, status, report_path, started_at, finished_at）。

### 5.2 接口设计（建议）

- [ ] 用例：`GET/POST/PUT/DELETE /api/ui-test/cases`。
- [ ] 执行：`POST /api/ui-test/cases/{id}/run`，后端调用 Karate（JUnit 或 ProcessBuilder），将报告路径写入 `ui_run`，返回执行 ID 与报告 URL。
- [ ] 报告：`GET /api/ui-test/runs/{id}` 返回执行状态与报告路径；报告文件可由静态资源或单独接口提供。

### 5.3 后端实现

- [ ] 搭建 Karate 子模块或内嵌：能执行指定 `.feature` 或传入脚本内容，输出 HTML 报告到固定目录。
- [ ] 实现用例 CRUD、run、查询执行记录与报告路径。

### 5.4 可交付

- 用 Postman 能：创建 UI 用例、触发执行、查询到报告路径并可打开 HTML 报告。

## 阶段 6：UI 测试 - 前端

**目标**：在「进入 UI 测试平台」后的页面中，完成用例列表、执行、报告查看。

### 6.1 页面与路由

- [ ] 路由：`/ui-test/app` 为 UI 测试主页（用例列表）。
- [ ] 用例列表：展示用例名称、最近执行时间等，可新建、编辑、删除、执行。
- [ ] 执行：点击执行后显示执行中状态，完成后可点击「查看报告」打开 Karate 报告（新窗口或 iframe）。

### 6.2 与后端对接

- [ ] 调用阶段 5 的 cases、run、runs 接口。

### 6.3 可交付

- 从门户「进入 UI 测试平台」→ 能管理用例、执行、查看报告。

## 建议执行顺序

1. **按阶段 0 → 1 → 2** 做完，先有「可登录的门户 + 说明页 + 入口按钮」。
2. **再按阶段 3 → 4** 完成接口测试端到端。
3. **再按阶段 5 → 6** 完成 UI 测试端到端。
4. **最后阶段 7** 联调与文档。

每完成一个阶段可在文档中勾选对应 checkbox，便于跟踪进度。若某阶段需要更细的接口定义或表结构，可在 `docs/` 下单独补充（如 `接口测试-接口说明.md`）。
